# BiliTask

B站每日任务本地控制台：扫码登录、每日登录、观看、投币、分享，每天北京时间 07:00 自动执行。

## 使用

需要 Node.js 20 或以上版本。

```bash
npm install
npm start
```

浏览器访问 `http://localhost:8000`，使用 B站 App 扫码。首次运行自动创建 `config.json`，登录凭据仅保存到本机，不提交到 Git。保持程序运行，定时任务才会触发。

- `npm stop`：停止程序。
- `npm test`：运行后端、接口与前端 DOM 回归测试。全部使用模拟接口，不连接 B站，也不消耗硬币。
- `npm run preview`：在 `http://localhost:8001` 查看设计预览，使用示例账号和内存模拟数据，不连接 B站，不启用真实定时任务。
- `node scripts/build-preview.js`：在项目上级目录生成 `BiliTask-preview.html`，可离线打开；其中的运行、设置、退出均为模拟操作，刷新文件恢复示例数据。
- `PORT=8002 npm start`：指定端口（Windows PowerShell 使用 `$env:PORT=8002; npm start`）。
- 设置环境变量 `BILITASK_NO_OPEN=1` 可关闭启动后自动打开浏览器。

## 界面

- 总览、任务设置、运行记录三个视图，适配手机和桌面。
- 轻量液态玻璃、卡片光照跟随、低幅度卡片倾斜和按钮鼠标反馈。
- 深浅主题、自定义主题色、可关闭鼠标动效；自动尊重系统“减少动态效果”。
- 键盘可操作的标签页与开关、加载状态、错误重试和保存反馈。
- 日志使用文本节点渲染，避免视频标题等外部内容被当作 HTML 执行。

设计借鉴 [Arc UI](https://uiarc.dev/) 的组件层级、柔和渐变和细微交互，使用本项目自己的原生 HTML/CSS/JavaScript 实现，无需 React 构建步骤。

## 任务行为

- 手动执行与定时任务共享运行锁，防止重叠投币。
- 运行前确认登录、等级与每日任务状态；无法确认时停止，避免按“零完成”继续投币。
- Lv.6 账号在后端停止全部每日任务，定时运行也会跳过。
- 投币目标为今日累计 1–5 枚，按 `2+2+1` 等方案分配，使用不同视频，成功结果按实际枚数累计；投币会同时点赞。
- 在同一程序进程、同一北京时间日期、同一账号下，额外记住已确认成功的投币请求，即使奖励状态延迟也不会再次补投。投币请求网络异常、结果不确定时，暂停本进程该账号当天的后续投币。该保护记录在内存中，重启后不保留，因此不要通过重启程序反复尝试不确定的投币；先核对 B站记录。
- 观看、分享的“请求接受”与“任务完成”分开处理；本次确认经验按运行前后奖励状态差计算，可能因接口延迟显示 0。
- 分享任务可关闭。移动端模拟分享不保证计入经验；每日预估和升级天数只是按配置计算的计划值。
- 最近一次运行记录保存在当前进程内，重启或切换账号后不保留。

## 本地访问与头像代理

服务绑定 `127.0.0.1`。Host 必须为当前端口的 `localhost` 或 `127.0.0.1`；拒绝跨站来源和跨站 fetch，写操作需要控制台自定义请求头。不要直接改为对公网监听。

头像代理仅接受 HTTPS 的 `hdslb.com` 或其子域名，禁止自定义端口、URL 凭据和重定向，限制下载时间和体积，并只接收常用栅格图片格式。

B站接口的实际可用性和经验奖励仍需用户使用自己的账号验证。本次回归测试不包含真实扫码登录、观看、投币或分享。
